# 소프트웨어 설계 요약

## 기본 개념
- **품질 속성**: 성능, 신뢰성, 보안성, 유지보수성 등.
- **워크플로우**: 요구사항 분석 → 설계 → 구현 → 테스트 → 유지보수.
- **아키텍트**: 요구사항과 품질 속성을 고려해 전체 구조를 설계하는 역할.
- **UML**: 시스템의 구조와 동작을 그림으로 표현하는 모델링 언어.
- **서버·클라이언트**: 클라이언트가 요청하고 서버가 처리·응답하는 구조.

## Rust에 적용

| 설계 개념 | Rust 적용 |
|---|---|
| 캡슐화 | 비공개 필드 + `pub` 메서드 |
| 인터페이스 | `trait` |
| 다형성 | 제네릭 + 트레이트 / `dyn Trait` |
| 상속 대신 기능 재사용 | 구조체 조합 + 트레이트 |
| 높은 응집도 | 관련 기능을 한곳에 모으기 |
| 낮은 결합도 | 모듈 사이의 의존 줄이기 |

## SOLID

| 원칙 | 핵심 |
|---|---|
| S — 단일 책임 | 변경 이유가 하나가 되도록 책임 분리 |
| O — 개방·폐쇄 | 확장에는 열려 있고 수정에는 닫혀 있게 |
| L — 리스코프 치환 | 구현을 교체해도 동작의 약속 유지 |
| I — 인터페이스 분리 | 필요한 기능만 의존하도록 작게 분리 |
| D — 의존성 역전 | 구체적인 구현보다 추상화에 의존 |
